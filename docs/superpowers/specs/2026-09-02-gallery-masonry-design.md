# 图库无留白瀑布流设计

## 背景

精选、最近和随机浏览当前使用按行对齐的图库布局。当照片比例差异较大时，算法会产生单图行或短尾行，导致右侧和行间出现大块留白。图库需要在保留照片比例的同时，让内容连续填满可用宽度，并允许错落排列。

## 目标

- 精选、最近、随机三种模式共用无大块留白的瀑布流布局。
- 照片保持原始宽高比例，不因填充而变形。
- 通过平衡列高让照片墙错落、连续且视觉稳定。
- 保留现有照片点击打开、懒加载和滚动加载行为。
- 响应桌面、平板和手机宽度，不产生水平溢出。

## 非目标

- 不改变精选、最近、随机的排序和数据来源。
- 不改变照片详情页、影册展开或后台照片管理布局。
- 不引入第三方瀑布流依赖。

## 方案

### 布局模型

将 `PhotoGrid` 从“行 + 对齐高度”改为“列 + 平衡高度”。根据容器宽度选择列数：手机 1 列、小平板 2 列、桌面 3 至 5 列。每列是纵向布局，每张照片宽度相同，高度由照片 `aspectRatio` 计算。

照片按输入顺序依次放入当前预计总高度最小的列。预计高度使用列宽除以照片比例，并加上列内间距。该分配是确定性的，在相同输入、宽度和列数下始终得到相同结果。

### 数据流

```text
gallery store 排序 -> PhotoGrid 获取照片和容器宽度
                  -> 计算列数和列宽
                  -> 按最短列分配照片
                  -> 渲染列和 PhotoCard
                  -> 滚动追加时只分配新增照片
```

精选、最近、随机仍由 `gallery` store 负责排序，`PhotoGrid` 只处理布局。

### 追加和重排

- 首次加载或模式切换：清空旧列，根据当前照片顺序重新分配。
- 同一模式追加照片：保留已有列，只把新增照片放入当前最短列。
- 容器宽度变化：使用 `requestAnimationFrame` 合并连续尺寸变化，再按新列数重排。
- 每个照片单元使用 `aspect-ratio`，图片加载前后保持稳定占位，降低滚动跳动。

## 响应式规则

- 小于 620px：1 列，列内间距 8px。
- 620px 至 999px：2 列，间距 10px。
- 1000px 至 1499px：3 列，间距 12px。
- 1500px 至 1799px：4 列。
- 1800px 及以上：5 列。

页面左右边距沿用现有 `gallery-content`，列宽通过容器宽度平均计算，禁止水平滚动。

## 异常处理

- 容器宽度尚未测得时使用安全默认列数，测得真实宽度后在下一帧重排。
- 缺少或非法比例时按 `1` 处理，避免零高度或无限高度列。
- 空列表渲染为空，不创建空列。
- 组件卸载时取消未执行的动画帧和尺寸监听。

## 测试

### 单元测试

- 空列表不生成列。
- 不同比例照片会按最短列分配。
- 相同输入和宽度得到稳定分配结果。
- 追加照片不改变已有照片所在列。
- 不同容器宽度得到合理列数，比例异常时仍有有效高度。

### E2E 与视觉检查

- 精选、最近、随机模式均能显示照片墙，不出现整行右侧大块空白。
- 桌面、平板、手机视口无水平溢出，图片比例正常。
- 模式切换不闪烁、不乱跳，滚动加载后已有照片位置保持连续。
- 照片仍可点击打开详情，懒加载和分页请求保持正常。

### 回归

运行 Web 单测、图库相关 E2E、视觉测试、类型检查、lint 和生产构建。

## 验收标准

在精选、最近和随机浏览中，不论照片横竖比例如何，页面都呈现连续、错落、填满宽度的照片墙，不再出现当前截图中的单图行和大块留白；现有排序、点击打开和滚动加载行为不变。
