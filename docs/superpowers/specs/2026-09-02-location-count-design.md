# 地区照片数量完整统计设计

## 背景

图库顶部的地区选择器目前直接使用 `gallery.locationPhotos` 计算每个省份或国家的照片数量。该数组跟随图库分页加载，首屏只包含第一批照片，因此用户没有滚动图库时，地区数量会少于工作区内实际的公开照片数量。

## 目标

- 地区选择器统计当前工作区内全部已发布且可见的照片。
- 支持超过单页接口限制的照片数量。
- 不改变图库首页的首屏分页、滚动加载、排序和地区筛选行为。
- 统计目录请求失败时，不阻塞图库的正常使用。

## 方案

在 gallery store 中增加独立的地区统计目录。目录加载方法调用现有公开图库接口，固定使用 `featured` 模式和 `limit=100`，根据响应中的 `nextCursor` 循环请求所有页面。每页结果通过现有 `toGalleryPhoto` 转换，并按照片 ID 去重后保存。

地区目录与首页展示列表分离：

- `photos` 继续表示当前模式已加载的照片，服务于首页展示和无限滚动。
- `locationPhotos` 改为完整的地区统计目录，或由完整目录替代其原有首批缓存语义。
- 地区选择器从完整目录生成 `LocationOption`，继续使用 `buildLocationOptions` 的省份别名、地点名称和 `locationRegion` 匹配规则。
- 用户实际选择地区后，照片列表仍请求 `mode=location`，由服务端分页返回结果。

目录加载与当前图库请求使用独立的请求控制和请求序号。工作区、登录状态或公开用户上下文变化时，旧目录请求失效并清空；新上下文重新加载。目录请求失败只记录可恢复状态，并保留已有目录内容，不改变 `gallery.error`，避免干扰图库页面。

## 界面行为

`GalleryView` 在工作区上下文准备完成后启动目录预取。`CategoryNav` 和 `LocationPicker` 继续通过响应式照片数组接收数据，因此目录完成后数量会自动刷新。打开选择器不需要等待目录请求；加载中的数量可以暂时使用已有照片，完成后更新为完整数量。

## 边界与错误处理

- API 按最多 100 条一页请求，直到 `nextCursor` 为空；每页照片按 ID 去重。
- 服务端公开接口已过滤未发布、隐藏和仅所有者可见照片，前端不扩大可见范围。
- 如果某一页请求失败，保留已经成功合并的目录，并允许后续上下文变化时重新加载。
- 如果目录尚未完成，地区选项仍沿用已有照片生成，避免界面空白。

## 测试

- store 测试：多页响应合并、重复 ID 去重、上下文切换丢弃旧请求、失败时保留已加载目录。
- 地区选项测试：完整目录中的多条照片都计入对应省份，带展示省份但地点名称不含省份的照片仍能归类。
- 回归检查：Web 类型检查、Web 单元测试、生产构建和 `git diff --check`。

## 非目标

- 不新增 API 端点或修改服务端照片权限规则。
- 不一次性将完整目录渲染到图库首页。
- 不改变地区筛选后的照片排序和分页逻辑。
