# 精选、最近、随机滚动稳定性设计

## 目标

消除首页精选、最近、随机模式在鼠标滚轮滚动和触发分页时的跳动，保留当前照片比例、全宽 justified-row 视觉和无限滚动体验。

## 已确认的行为

- 最近模式按拍摄时间从新到旧展示，最新照片位于前面。
- 精选模式按评分从高到低展示；同评分按画幅比例、标题和照片 ID 稳定兜底。
- 随机模式在一次浏览会话中使用固定随机种子；重新选择随机时才生成新种子。
- 加载下一页后，已显示照片的顺序和屏幕位置不改变，新照片按当前模式的顺序追加到正确位置。
- 登录用户、公开用户影册、未登录默认照片和公开性过滤规则不变。

## 方案

### 1. API 排序契约

- `/spaces/:slug/photos?mode=recent` 只按原始 ISO `capturedAt` 从新到旧排序，使用 ID 作为相同时间的稳定兜底。
- `featured` 在服务端使用评分、画幅比例、标题和 ID 的确定性比较器，前端不再对 API 返回数据二次排序。
- `shuffle` 接收无符号整数 `seed` 参数，服务端使用与前端一致的 seeded FNV 排名函数；分页游标始终基于同一 seed。
- 未传 seed 时服务端继续使用固定的稳定排序，保证兼容旧客户端。

### 2. 前端数据流

- Gallery store 在随机模式生成并保存 seed，所有首屏和追加请求复用该 seed。
- API 模式的精选、最近、随机直接使用服务端顺序；仅离线 demo 数据保留本地排序逻辑。
- 切换模式时中止前一个请求，只有当前请求可以更新照片列表和分页游标。
- 追加请求确认游标属于当前模式后才合并数据，避免快速切换时串入旧模式结果。

### 3. 稳定网格

- justified-row 布局按已加载数据维护行状态。
- 已经进入视口的行冻结照片、顺序和高度；追加数据只计算底部活动行/新行。
- 图片尺寸变化不触发行高重算，容器宽度真正变化时才通过 `ResizeObserver` 重新布局。
- 行节点使用稳定 key，避免 Vue 因数组更新重建已有照片节点。

## 错误与兼容性

- 请求取消属于正常流程，不显示错误提示，也不覆盖当前模式数据。
- seed 必须是客户端生成的合法无符号整数；接口对非法 seed 返回校验错误。
- 不改变公开照片过滤、权限校验、照片查看器和对象存储地址。
- 低动效设置继续禁用入场动画；滚动期间不增加额外动画。

## 测试与验收

- API 单测覆盖最近排序、精选同分排序、seeded shuffle 跨分页一致性。
- Store 单测覆盖最近不反转、随机 seed 复用和模式切换取消旧请求。
- 布局单测覆盖追加数据时已有行高度/顺序保持不变。
- 端到端测试覆盖滚轮滚动触发分页、快速切换精选/最近/随机、首屏锚点位置和无横向溢出。
- 运行全仓库测试、类型检查、lint、生产构建及桌面/移动浏览器验证。
