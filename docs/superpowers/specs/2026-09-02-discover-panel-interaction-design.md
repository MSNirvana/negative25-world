# 地图地点面板交互设计

## 背景

地图左侧的精选和近期更新区域已经渲染地点卡片，但在实际地图页面中，卡片点击和横向滑动容易被地图手势或滚动容器行为干扰。地点搜索目前只覆盖有限字段，用户输入省份、地点原始名称或别名时可能没有结果。

## 目标

- 精选和近期更新中的每张地点卡片都可以点击并打开对应详情。
- 地点卡片轨道支持触摸左右滑动、触控板横向滚动和鼠标滚轮横向滚动。
- 面板交互不会触发地图拖拽、缩放或地图点击筛选。
- 搜索实时匹配地点名称、slug、照片地点原始字段、省份、照片标题和照片描述。
- 保持现有简约布局，不增加左右箭头等额外控件。

## 方案

继续使用现有的原生横向滚动轨道，不引入自定义拖拽状态。为地点面板和每条地点轨道补充事件隔离，使点击、触摸和滚轮事件在面板内消费，不冒泡到 AMap 容器。轨道设置横向触摸行为、横向 overscroll containment 和移动端惯性滚动；当鼠标滚轮主要产生垂直 delta 时，将 delta 转换为轨道的 `scrollLeft`，让普通鼠标也能浏览卡片。

卡片仍通过 `select-location` 事件传递完整的 `DiscoverLocation`，桌面端显示右侧详情，移动端进入现有地点详情路由。卡片点击不改变地图缩放逻辑。

搜索过滤函数集中在 `discover-map-data`，将地点的展示名称、slug、每张照片的 `location`、`locationName`、`locationRegion`、标题和描述合并为检索文本后做大小写不敏感匹配。这样省份字段隐藏在照片展示地址中时仍可找到对应地点。

## 边界与兼容性

- 没有横向溢出时，滚轮事件不改变页面垂直滚动；有横向内容时只移动当前轨道。
- 鼠标右键、中键和键盘操作保持浏览器默认行为；地点按钮仍支持 Enter/Space。
- 搜索无结果时沿用现有空状态，不隐藏搜索输入。
- 地图点击筛选圆圈只在事件目标属于地图本身时触发，面板事件不会进入该逻辑。

## 测试

- 增加 `filterLocations` 测试，验证省份、地点原始字段和照片描述可搜索。
- 运行 Web 类型检查、全部 Web 单元测试、生产构建和 `git diff --check`。
- 手动验证桌面和移动视口：卡片点击打开详情，轨道可横向滑动，地图不会随面板手势移动。

## 非目标

- 不改变地点数据来源、照片数量统计或地图标记聚合。
- 不新增 API 端点。
- 不改动详情页和照片查看器的返回逻辑。
