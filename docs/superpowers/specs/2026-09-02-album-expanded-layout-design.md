# 影册展开布局优化设计

## 目标

修复首页“影册”展开后的照片排列问题：照片必须按评分高低展示，不因照片比例不同产生大片空白，并充分利用内容区域右侧空间。

## 已确认的行为

- 展开相册时，照片按评分降序排列。
- 同评分照片按拍摄时间从新到旧排列。
- 未评分照片统一排在已评分照片之后。
- 相册封面只影响收起状态的堆叠封面，不改变展开后的评分排序。
- 展开后点击照片仍打开现有照片查看器；点击照片以外的空白区域仍收起相册。

## 方案

复用 `PhotoGrid` 的 justified-row 布局思路，为 `AlbumStacks` 的展开区域提供相同的全宽行布局：

1. 将相册原始 `PhotoSummary` 先排序，再转换为 `GalleryPhoto`，避免使用本地化后的日期字符串参与排序。
2. 根据容器宽度、照片原始宽高比和目标行高动态分行。
3. 每个非末行按比例计算单元格宽度，使整行填满容器；末行限制高度，避免少量照片被放大。
4. 展开区域宽度改为 100%，仅保留页面既有左右内边距；桌面端三列固定宽度的限制不再适用。
5. 移动端使用更小间距和较低目标行高，保持完整的横向利用率。

## 数据流与边界

- `GalleryView` 继续负责加载相册详情和维护当前展开相册 ID。
- `AlbumStacks` 负责展开相册的排序、分行和交互事件，不修改后端相册接口。
- 缺失评分按 `-1` 参与比较；缺失拍摄时间按空值处理，排在同评分且有时间的照片之后；最终以照片 ID 作为稳定兜底排序。
- 照片原始比例异常时使用与现有 `PhotoGrid` 相同的最小比例保护，避免零尺寸或极端高宽比破坏布局。

## 错误与兼容性

- 不改变照片加载、公开性过滤、相册权限或大图查看逻辑。
- 空相册继续显示现有空状态。
- `ResizeObserver` 不可用时使用初始容器宽度，布局仍可渲染；减少动画设置继续禁用展开和照片入场动画。

## 验收与测试

- 单元测试覆盖：评分降序、同评分按拍摄时间降序、未评分置后、ID 稳定兜底。
- 单元测试覆盖：分行后每个非末行宽度等于容器宽度，末行不产生异常放大。
- 手工/浏览器验证：桌面宽屏、普通桌面、手机宽度下展开相册，确认右侧无未使用的半屏区域、比例不同照片不出现网格型空白、点击空白可收起、点击照片可打开查看器。
- 运行 Web 类型检查、单元测试和生产构建。
