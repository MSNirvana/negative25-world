# 照片显示地址与省份前缀设计

## 背景

照片管理当前支持通过地图搜索地点并保存地点名称、经纬度。首页和照片详情直接使用标准地点名称作为展示文案，导致定位数据与面向访客的短地址混在一起，也无法为地点显示统一的省份或地区前缀。

本功能为每张照片增加独立的“显示地址”配置：定位地址继续服务于地图、位置筛选和地点聚合；显示地址服务于首页及公开照片详情的文案展示。显示地址由搜索结果自动填充，但允许用户手动修改。

## 目标与非目标

### 目标

- 在照片管理编辑器中区分“定位地址”和“显示地址”。
- 选择地图搜索结果后，自动填充显示地址及可用的省份/地区信息。
- 每张照片独立控制是否显示省份/地区前缀，默认开启。
- 首页照片卡片和公开照片详情显示配置后的地址。
- 保持地图、位置筛选、发现地图使用标准定位数据。
- 兼容已有照片，未配置新字段时继续显示原地点名称。

### 非目标

- 不改变地图供应商、搜索接口或坐标系统。
- 不新增独立的照片地址数据库表或数据库列。
- 不把手动显示地址用于地点聚合、位置筛选或地图反向定位。
- 不为没有行政区信息的地点强行猜测省份/地区。

## 术语与数据模型

- **定位地址**：地图搜索结果对应的标准地点名称、经纬度及地点 ID。当前继续存储在照片的 `location`、`latitude`、`longitude` 和现有定位元数据中。
- **显示地址**：访客看到的短地址文本，存储在照片 metadata 的 `displayAddress`。
- **显示地区**：从地图搜索结果提取的省份、直辖市、自治区、特别行政区或其他国家/地区名称，存储在 `displayRegion`。
- **地区前缀开关**：布尔值 `displayRegionEnabled`，表示是否在显示地址前添加显示地区。

推荐的 metadata 结构如下：

```json
{
  "displayAddress": "鹳雀楼",
  "displayRegion": "山西",
  "displayRegionEnabled": true
}
```

字段均为可选，以兼容历史照片。`displayRegionEnabled` 仅在照片编辑保存后明确写入；对新选择的地点默认写入 `true`。旧照片没有该字段时，展示逻辑按原地点名称回退，不改变历史数据。

## 交互设计

### 照片管理编辑器

现有地图定位组件继续作为“定位地址”入口：

1. 用户在搜索框输入地点并选择一个搜索结果。
2. 组件向父级返回地点名称、地址/行政区信息、经纬度和可用的省份/地区。
3. 父级更新标准定位字段，同时将显示地址默认设置为搜索结果的地点名称，将显示地区设置为搜索结果提取的行政区，并将地区前缀开关设为勾选。
4. 编辑器显示“显示地址”文本输入框，用户可直接修改文本。
5. 编辑器显示“显示省份/地区前缀”复选框，每张照片独立保存。
6. 用户再次选择新的搜索结果时，显示地址、显示地区和前缀开关按新结果重新自动填充；用户随后仍可再次手动修改显示地址或取消勾选。
7. 点击清除定位时，同时清除定位地址、坐标、显示地址、显示地区和地区前缀开关，避免留下无定位的展示文案。

保存时，定位字段和显示字段在同一次照片更新请求中提交。显示地址为空时不生成前缀，首页回退到标准地点名称或坐标。

### 展示格式

展示文本由统一格式化函数生成：

- `displayRegionEnabled === true` 且地区和显示地址均非空：`地区·显示地址`。
- 关闭开关或地区为空：`显示地址`。
- 没有显示地址：回退到标准定位名称。
- 没有任何地点：继续使用现有“未指定地点”文案。
- 如果手动输入的显示地址已经以同一地区和分隔符开头，不重复添加前缀。

示例：

| 显示地区 | 显示地址 | 开关 | 最终展示 |
| --- | --- | --- | --- |
| 山西 | 鹳雀楼 | 开 | 山西·鹳雀楼 |
| 山西 | 鹳雀楼 | 关 | 鹳雀楼 |
| 空 | Dolomites | 开 | Dolomites |
| 山西 | 山西·鹳雀楼 | 开 | 山西·鹳雀楼 |

### 首页与公开详情

`toGalleryPhoto()` 统一把最终格式化后的显示文本映射到 `GalleryPhoto.location`，因此首页照片卡片、照片元数据行和照片详情面板使用同一结果。发现地图和位置筛选使用 `locationId`、标准 `location.name` 和坐标，不使用显示地址，避免手动文案造成同一地点拆分成多个地点。

## 行政区信息提取

地图搜索组件扩展搜索结果的内部类型，优先读取高德 POI 返回的省份/地区字段（如 `pname`），并按以下规则清理：

- 去除“中国”“省”“市”“自治区”“特别行政区”等后缀，保留访客熟悉的简称，例如“山西省”转为“山西”。
- 直辖市保留“北京”“上海”等名称作为地区前缀。
- 海外地点优先使用供应商返回的国家/地区字段；字段缺失时地区为空。
- 只把行政区信息作为显示地区保存，不改变标准地点名称和坐标。

## API 与持久化

- 扩展管理员照片更新请求的 `location` 相关 payload，增加可选的 `displayAddress`、`displayRegion`、`displayRegionEnabled` 字段。
- 管理服务校验并清理字符串：显示地址和地区去除首尾空白，限制合理长度；开关必须为布尔值。
- 保存定位时把显示字段写入 photo metadata；清除定位时删除这些字段。
- 公开照片接口继续返回 metadata，前端负责兼容旧照片并生成最终展示文本。
- 不新增数据库迁移；Postgres 和内存仓库沿用现有 metadata 序列化路径。

## 错误处理与兼容性

- 地图搜索失败不影响手动编辑已有显示地址，但无法生成新的地区前缀时不显示前缀。
- 显示地址保存失败时保持编辑器打开，并保留用户输入，提示现有照片保存错误文案。
- API 返回未知或缺失的新 metadata 字段时，前端按旧地点名称回退，不阻塞照片列表加载。
- 未配置地区前缀的历史照片不自动批量改写；用户编辑并保存后才生成新字段。

## 测试范围

### 单元测试

- 行政区名称清理：省、直辖市、自治区、特别行政区、海外地区和空值。
- 显示地址格式化：开关开/关、地区缺失、地址为空、重复前缀。
- `toGalleryPhoto()` 对新字段和旧照片回退的转换。
- 管理服务保存和清除 display metadata。

### 组件/接口测试

- 选择搜索结果会自动填充显示地址、地区和默认勾选状态。
- 手动修改显示地址及切换复选框后，保存请求携带正确字段。
- 清除定位会清除显示字段。
- 首页卡片和详情展示最终显示地址，发现地图仍使用标准定位。

### 回归验证

- Web 类型检查、现有 Web/API 测试和 `git diff --check`。
- 在当前开发端口验证照片管理编辑器和首页展示，不改变现有 5173/5175 服务。
